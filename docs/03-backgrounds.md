# 03. Фоны: провайдеры, лимиты, промпты

## Чем генерировать

| Провайдер | Ключ | Цена | Формат | Качество | Статус |
|---|---|---|---|---|---|
| **Cloudflare Workers AI** | `cloudflare.json` | 10 000 neurons/день бесплатно, карта не нужна | 1024×1024, скрипт кропает до 4:3 | FLUX.1-schnell — хорошая детализация, но 1024 px | **Рабочий выбор** |
| Google (Gemini image) | `google_api_key.txt` | ~$0.0336 за 1K-картинку, free tier у image-моделей отсутствует | до 4K | лучшее качество | Нужен биллинг |
| Stability AI | `stability_api_key.txt` | 25 кредитов новому аккаунту | просит 3:2, кроп до 4:3 | SD3.5 | Ключа нет |
| Hugging Face | `hf_token.txt` | бесплатных кредитов нет | — | FLUX.1-schnell | `402 Purchase pre-paid credits` |
| Pollinations | не нужен | бесплатно, без ключа | размер задаётся `--width/--height` | нестабильное | Резерв |

Практический порядок выбора: **Cloudflare** → Google (если появится биллинг) → Pollinations. Всегда указывать `--provider` явно, иначе `auto` может уйти к другому провайдеру, как только появится ключ.

## Настройка Cloudflare

1. Аккаунт на `dash.cloudflare.com` (карта не требуется).
2. В левом меню — **AI → Workers AI**, включить продукт.
3. **My Profile → API Tokens → Create Token**, шаблон с правом `Workers AI: Read` (или custom token с этим правом).
4. Account ID — на странице **Workers & Pages** справа, либо в URL дашборда.
5. Сохранить в `%LOCALAPPDATA%\rembg-env\cloudflare.json`:

```json
{
  "account_id": "<account_id>",
  "token": "cfat_..."
}
```

Альтернатива — переменные окружения `CLOUDFLARE_ACCOUNT_ID` и `CLOUDFLARE_API_TOKEN` (они приоритетнее файла).

Проверка без генерации:

```powershell
curl.exe -4 -s -H "Authorization: Bearer $env:CLOUDFLARE_API_TOKEN" `
  "https://api.cloudflare.com/client/v4/accounts/$env:CLOUDFLARE_ACCOUNT_ID/ai/models/search?per_page=5"
```

Важно: эндпоинт `/user/tokens/verify` для токенов Workers AI отдаёт `Invalid API Token`, хотя токен рабочий. Проверять именно запросом к `/accounts/.../ai/`.

### Модель и расход

```text
@cf/black-forest-labs/flux-1-schnell
```

- 4 шага инференса, генерация 5–20 секунд.
- Расход — примерно 4.8 neurons за тайл 512×512 плюс 9.6 neurons за шаг; одна картинка 1024×1024 укладывается в десятки neurons.
- Дневной бесплатный лимит — 10 000 neurons, то есть несколько сотен черновиков в день.

## Команда генерации

```powershell
$root = "C:\My_projects\Photo"
$data = "$root\data"
$py = "$root\.venv\Scripts\python.exe"
$pp = "$root\src\photo_pipeline.py"
Set-Location $root

& $py $pp genbg "<prompt>" "$data\bg\park-draft.jpg" `
  --provider cloudflare `
  --model "@cf/black-forest-labs/flux-1-schnell" `
  --no-upscale
```

- `--no-upscale` для черновиков: фон нужен 1024 px, апскейл только для выбранного варианта.
- `--width/--height` на Cloudflare не влияют на генерацию: модель всегда отдаёт 1024×1024, `_crop_aspect` кропает до 4:3 → 1024×768.
- `--size 1K|2K|4K` задаёт **конечный** размер файла (1024×768 / 2048×1536 / 4096×3072). Для Cloudflare 2K = те же 1024×768 → ESRGAN ×4 → уменьшение до 2048×1536; 4K = ×4 без уменьшения. Preset важнее `--no-upscale`.
- Русский промпт переводится на английский (`src.core.prompt`, без ключа); «в 2К» из текста удаляется — размером управляет `--size`. Проверено на промпте «Скалистый берег Северного ледовитого океана…»: результат ровно 2048×1536.
- Один и тот же промпт даёт разные картинки: модель недетерминирована. Поэтому черновики генерируются по 3–5 штук.

## Промпты

### Утверждённый вариант C

```text
photorealistic quiet city park in late afternoon, low golden sun from the right,
backlit oak trees, long shadows, wooden bench, grass and path, realistic photo, no people
```

Что сработало: конкретный тип парка, время дня, направление света, перечисление объектов (деревья, скамейка, трава, дорожка) и явный запрет людей.

### Черновики A и B

Те же слагаемые, но с другими акцентами: A — более открытая аллея с сильным закатом в кадре, B — плотные деревья и тёплый контровой свет. C выиграл за счёт того, что солнце не бьёт в объектив и тени на земле читаются мягче.

### Шаблон промпта

```text
photorealistic <место> in <время дня>, <характер света>, <2–3 объекта>,
<передний план>, <средний план>, <фон>, realistic photo, no people, no text
```

Обязательные хвосты: `realistic photo`, `no people`, `no text`. Без `no people` модель почти всегда ставит фигуры на дорожку.

## Правило выбора фона по свету

Главный источник брака в композите — рассогласование света. Портрет освещён слева и мягко, а фон «светит» справа и жёстко: тени на земле и на лице живут в разных мирах, и глаз это ловит сразу.

Поэтому для будущих фонов:

- **без видимого источника света** — без диска солнца, без лучей, без яркого пятна в кадре;
- **мягкий рассеянный свет** — облачность, пасмурный день, глубокая аллея, тень от крон;
- **ровная освещённость** — без длинных резких теней на земле и без контрового ореола;
- если источник всё же в кадре, его направление должно совпадать с направлением света на лице модели.

Формулировки для промпта: `soft overcast light`, `shaded alley`, `diffused daylight`, `no direct sun`, `no sun in frame`. Избегать: `sunset in frame`, `sun flare`, `golden hour backlight` — они дают яркий диск и резкие тени.

Утверждённый вариант C — компромисс: низкое солнце справа есть, но само солнце в кадр не попадает, а тени мягкие. На будущее приоритет — полностью без источника.

## Апскейл

```powershell
& $py $pp upscale "$data\bg\park-c.jpg" "$data\bg\park-c-4x.jpg"
```

- Real-ESRGAN ×4, локально, без обращения к провайдеру: 1024×768 → 4096×3072.
- Это не «настоящие» детали, а реконструкция; при композите обязателен `--blur 0.5–0.8`, иначе фон мылит.
- Альтернатива — генерировать сразу в 2K/4K у Google, если появится биллинг.

## Порядок работы с фоном

1. 3–5 черновиков по одному промпту с разными seed/формулировками.
2. Контактный лист `src\contact_sheet.py` и оценка рядом.
3. Выбранный вариант → апскейл ×4.
4. Композит с `--blur 0.5`, проверка по чек-листу из [02-workflow.md](02-workflow.md).
5. Не понравилось — возврат к шагу 1, а не «лечение» композита ползунками.
