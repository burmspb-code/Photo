# 05. Типичные ошибки

## Сеть

### Запрос висит и не завершается

Причина — IPv6 в этой сети. В `src\core\settings.py` стоит патч `socket.getaddrinfo`, который принудительно ходит через IPv4 (при импорте ядра, до загрузки rembg), поэтому сам пайплайн не страдает. Сторонние клиенты патча не имеют.

```powershell
curl.exe -4 -sS "https://api.cloudflare.com/client/v4/"
```

Python без патча и Node `fetch` будут таймаутиться. Лечится только IPv4 или VPN.

### Cloudflare: `WinError 10054` / `Recv failure: Connection was reset`

TCP до `api.cloudflare.com` устанавливается за ~0.04 с, но TLS-handshake срывается через ~19–21 с. Это **фильтрация по SNI** на пути трафика, а не проблема ключа или кода: одинаково рвутся `api.`, `dash.`, `www.cloudflare.com`, `pages.dev`, `cf.com`, `discord.com`, но проходят `https://1.1.1.1`, `workers.dev` и обычные сайты. Проверка (без утечки токена):

```powershell
curl.exe -4 -v --max-time 25 -o NUL https://api.cloudflare.com/client/v4/
# Trying 104.19.192.29:443 -> ALPN offer -> Recv failure: Connection was reset
curl.exe -4 -k -o NUL -w "http=%{http_code} total=%{time_total}" `
  -H "Host: api.cloudflare.com" https://104.19.192.29/client/v4/
# http=404 total=0.2  — без SNI соединение проходит
```

Обход через IP + `Host` для генерации **непригоден**: ответ API приходит (~0.24 с до первого байта), но передача обрывается на ~25 КБ от ~760 КБ (картинка не скачивается). Вариант с чужим разрешённым SNI (`workers.dev`) даёт `403` — Cloudflare роутит по SNI, а не по `Host`.

Лечение — вернуть VPN/exit node, чтобы трафик шёл мимо фильтрующего провайдера. Проверить:

```powershell
& "C:\Program Files\Tailscale\tailscale.exe" exit-node list   # не должно быть "no exit nodes found"
& "C:\Program Files\Tailscale\tailscale.exe" status
netsh winhttp show proxy                                       # при включённом прокси — не "Прямой доступ"
```

В `%USERPROFILE%\AppData\Local\Temp` и реестре `HKCU:\...\Internet Settings` остаётся `ProxyServer = 127.0.0.1:2080` от старого локального прокси; если слушателя на 2080 нет, он не помогает.

### Cloudflare: `Invalid API Token` на `/user/tokens/verify`

Это нормально: токены, созданные под Workers AI, не проходят проверку на общем эндпоинте. Токен при этом рабочий. Проверять запросом к `/accounts/<id>/ai/models/search` или просто сгенерировать картинку.

### Cloudflare: `404` / `model not found`

Модель указана без префикса или устарела. Рабочее имя:

```text
@cf/black-forest-labs/flux-1-schnell
```

### Cloudflare: `Authentication error` / `Unable to authenticate request`

- не включён Workers AI в дашборде;
- у токена нет права `Workers AI: Read`;
- `account_id` и токен от разных аккаунтов;
- `cloudflare.json` лежит не в `%LOCALAPPDATA%\rembg-env\`.

### Hugging Face: `402 Purchase pre-paid credits`

У free-аккаунта HF нет бесплатных кредитов на inference, токен не помогает. Не тратить время, переключаться на Cloudflare.

### Hugging Face: `410 model is deprecated`

Старый маршрут `hf-inference` с `FLUX.1-schnell` отключён. Провайдер HF в этом проекте фактически нерабочий.

### Google: `403` / `billing required`

Imagen отключён, актуальны только Gemini image-модели, а у них нет бесплатного тарифа. Нужен включённый биллинг, ~$0.0336 за 1K-картинку. Без биллинга — Cloudflare.

### Stability: `401` без ключа

Ключа нет. Аккаунт даёт 25 кредитов, но их надо получить отдельно. Не приоритет, пока работает Cloudflare.

## Интерфейс

### Выпадающие списки «дёргаются» при открытии

Popup `QComboBox` — отдельное окно со своей палитрой. Если стилизовать только сам комбо, его view остаётся с системной палитрой (`#f3f3f3` на Windows): на тёмной теме список сначала рисуется светлым и только потом перекрашивается — выглядит как мигание/дёрганье. Проверить можно так:

```python
combo = dialog.controls["bg/provider_api"]
print(combo.view().palette().window().color().name())  # было #f3f3f3
```

Лечение — явные правила в `src\ui\styles.py`: `QComboBox QAbstractItemView` (фон `$menu_popup`, цвет `$text`, `selection-background-color: $accent`), `::item` и `::item:hover`. После правки снимок `view.grab()` даёт ровный тёмный фон `#1d2739` во всех строках.

**Стрелка.** Системный треугольник выглядит устаревшим, поэтому сейчас используется современный шеврон из PNG (`src\ui\icons\combo_arrow_dark.png` / `combo_arrow_light.png`), заданный через `QComboBox::down-arrow`. Обязательное условие: вместе с `::drop-down` задавать `::down-arrow` **и** состояния `:hover` / `:pressed`. Без них Qt убирает стрелку (проверка правой полосы: 0 контрастных пикселей вместо 30) и перерисовывает сабконтроль при каждом открытии — это и давало дёрганье. Регресс-тест `test_combo_arrow_is_visible` проверяет наличие шеврона по пикселям `combo.grab()`.

**Анимация.** Плавное появление реализовано в `src\ui\animated_combo.py`: `AnimatedComboBox.showPopup()` запускает одну `QPropertyAnimation` на `windowOpacity` (0 → 1, 170 мс, `OutCubic`). Popup — отдельное окно верхнего уровня `QFrame` (`combo.view().parent()`), поэтому анимировать нужно именно его, а не сам комбо. Старт отложен на один тик `QTimer.singleShot(0, ...)`, иначе Qt ещё не успел разместить popup. `hidePopup()` возвращает прозрачность в 1.0 и сбрасывает анимацию — повторное открытие не мигает. Тесты анимации — в `tests\test_animated_combo.py`.

**Важно: не анимировать `pos`.** Первоначально вместе с прозрачностью сдвигали popup вверх на 8 px. Покадровая проверка (см. ниже) показала, что локальная позиция выделенной строки не меняется (`row_local_y=76`), зато сам popup смещается по экрану: `global_y` шёл 6 → 14 и возвращался назад. Именно это выглядело как «строка выделения уезжает вниз при раскрытии и возвращается наверх». Сдвиг убран, осталась только анимация прозрачности. Диагностика — в `diag_highlight_visual.py` (в `%TEMP%\opencode`).

**Стрелки числовых полей.** У `QSpinBox`/`QDoubleSpinBox` системные треугольники тоже выглядят устаревшими, поэтому добавлены свои PNG-шевроны: `spin_up_{dark,light}.png` и `spin_down_{dark,light}.png`. В QSS заданы `::up-button`/`::down-button` (половина высоты поля, состояние `:hover`) и явные `::up-arrow`/`::down-arrow` с `image: url("$spin_up"/"$spin_down")`. Регресс-тесты — `test_spin_arrows_are_styled_in_both_themes` и `test_spin_arrows_are_visible`.

### Выбранная модель не восстанавливается в настройках

Тот же комбо с подсказками выявил вторую ошибку: `SettingsDialog._load()` определял «комбо с данными» по признаку `itemData(0) is not None`. У моделей в `itemData` лежит строка-подсказка, поэтому код уходил в ветку `findData(int(value))`, получал `ValueError` и оставлял первую модель вместо сохранённой. Теперь ветка по данным выбирается только когда `itemData(0)` — число (кратность апскейла); для остальных комбо используется `findText`. Регресс-тест пишет `cut/model = birefnet-portrait` в QSettings и проверяет, что диалог показывает именно её.

### Шапка диалога настроек отличается от фона

Один `DWMWA_USE_IMMERSIVE_DARK_MODE` красит системную строку заголовка в серый `#1c212c`, а фон окна по QSS — `#0f172a`; рядом видны два разных оттенка. `apply_dark_titlebar()` теперь дополнительно ставит `DWMWA_CAPTION_COLOR` (атрибут 35) в точный `$window` текущей темы. Цвет берётся из `THEME_WINDOW_COLORS` в `styles.py`, чтобы палитра не дублировалась. Замер по снимку экрана: до правки шапка `#1c212c` / клиент `#1f2530`, после — оба `#1f2530`.

На старых Windows атрибут 35 может не подействовать — тогда остаётся только тёмный режим, без точного совпадения оттенков (функционально это не ломает).

## Плагин и скрипт

### Namespace `photo` не появился

2. Проверить регистрацию в `~/.config/opencode/opencode.json`.

4. Если плагин держит старый снапшот кода — использовать CLI, результат идентичен.

### `composite` падает с ошибкой аргументов

Выходной путь обязателен третьим позиционным аргументом:

```powershell
& $py $pp composite "cut.png" "bg.jpg" "final.jpg"
```

Плагин подставляет путь сам, в CLI — вручную.

### `cut` идёт долго

1–2 минуты — норма: тайловый BiRefNet плюс pymatting. Не прерывать. На слабом CPU может быть дольше.

### В вырезке остался замкнутый «пробел»

Если модель оставила внутри объекта прозрачный участок (как на `DSCN1941.jpg` внизу кадра), он восстанавливается по маске цельного кадра: `global_shape_alpha()` и `merge_global_shape()` в `src\core\cutout.py` добавляют только области, где цельный кадр уверенно непрозрачен (>0,9), а тайлы почти прозрачны (<0,5). Цвет берётся из исходника до pymatting, поэтому залитый участок не отличается оттенком. Настоящие зазоры (между руками или ногами), прозрачные и на целом кадре, остаются прозрачными. Если пропуск не восстановился, проверьте альфу цельного кадра — возможно, модель приняла за объект весь нижний фон; в этом случае помогает обрезка кадра перед вырезкой. Если же участок альфы есть, но цвет в нём отличается, поможет `stabilize_alpha()`: при доле полупрозрачных пикселей выше 3 % внутренние области силуэта становятся полностью непрозрачными и pymatting уже не подбирает за них цвет. Одновременно она вычищает серый шум от перекрытий тайлов на больших кадрах.

Если же модель вырезала основной силуэт правильно, но вместе с ним захватила посторонний предмет или остаток фона **на расстоянии** от фигуры (как белый предмет в `CIMG8591.JPG`), поможет опция «Удалять обособленные элементы» на вкладке «Вырезка» (`cut/isolated`). Она убирает компоненты альфы, которые мельше `cut/isolated_ratio` (по умолчанию 15 % площади главного силуэта) и отделены от него хотя бы на `cut/isolated_gap` пикселей (по умолчанию 24). Оба условия обязательны: крупный отдельный фрагмент может быть частью объекта, а мелкий, но примыкающий — деталью силуэта. Если артефакт крупный или стоит вплотную, уменьшите долю/зазор в настройках; если, наоборот, вырезаются нужные детали — увеличьте. Все пороги вырезки доступны на этой же вкладке и дублируются флагами CLI `photo_pipeline.py cut`.

### Фон просвечивает сквозь волосы по краю головы

Если замкнутых дырок нет, но кайма вокруг головы полупрозрачна (альфа 0,05…0,5), поможет «Уплотнять кайму волос» (`cut/hair_refine`, вкладка «Вырезка»). Стадия `refine_hair()` в `src\core\cutout.py` увеличивает альфу в верхней `cut/hair_top_fraction` доле силуэта в `cut/hair_gain` раз, если пикселей каймы больше `cut/hair_min_mid`. Порог в абсолютных пикселях — защита эталонов: у `P1030034` кайма занимает 35 409 px, у остальных кадров не больше 18 032 px, поэтому правило меняет только проблемный кадр. Если уплотнение слишком заметно, уменьшите `cut/hair_gain`; чтобы применить правило к кадру с более узкой каймой, снизьте `cut/hair_min_mid`. Отключить стадию можно флагом `--no-hair-refine`.

### Голубой фон между прядями, а не по краю

Если фон светло-голубой и виден **внутри** головы (между прядями), уплотнение каймы не поможет: такие пиксели уже непрозрачны, у них альфа 1.0. В `P1030034` цвет фона RGB `(173,213,228)`, а пиксель просвета в точке `x=2064, y=805` имеет RGB `(157,195,206)` при альфе 1.0 — pymatting сохранил цвет фона как цвет «волос». Здесь нужна стадия «Убирать по цвету фона» (`cut/color_gaps`) — она делает такие пиксели прозрачными по цветовому расстоянию `cut/color_gap_lo…cut/color_gap_hi` (по умолчанию 45…100) в верхней `cut/color_gap_top_fraction` доле силуэта. Правило включается только если синий канал фона превосходит красный хотя бы на `cut/color_gap_min_blue` (25), поэтому кадры с тёплым фоном не меняются. Ослабить эффект можно повышением `cut/color_gap_lo`, отключить — флагом `--no-color-gaps`. Если голубой остался в нижней части фигуры, увеличьте `cut/color_gap_top_fraction`.

### `ModuleNotFoundError: No module named 'PIL'` / `cv2` / `numpy`

Зависимости не установлены в текущем интерпретаторе. В проекте они объявлены в `pyproject.toml`:

```powershell
Set-Location "C:\My_projects\Photo"

```

Если ошибка появилась при запуске через плагин — проверить, что `.venv\Scripts\python.exe` существует и что `poetry install` завершился без ошибок. Плагин в этом случае может откатиться на `rembg-env`.

### PyCharm: интерпретатор и запуск

- Интерпретатор проекта — `.venv\Scripts\python.exe` (Python 3.14), прописан в `.idea\misc.xml`.
- Он же используется для пайплайна: `rembg`, `onnxruntime`, `opencv`, `pillow`, `pymatting` установлены в `.venv`.
- Run Configuration: script `src\photo_pipeline.py`, working directory — корень проекта, аргументы — как в CLI.

### Poetry: `Readme path ... does not exist`

`pyproject.toml` ссылается на `README.md` в корне проекта. Файл должен существовать, иначе `poetry build`/`install` ругаются. В проекте он есть — короткое описание со ссылкой на документацию.

### Плагин не видит проектный скрипт

Плагин выбирает `.venv\Scripts\python.exe` и `src\photo_pipeline.py`, если они существуют; иначе — `rembg-env`. Принудительно задать пути:

```powershell
$env:PHOTO_PROJECT = "C:\My_projects\Photo"
$env:PHOTO_PYTHON = "C:\My_projects\Photo\.venv\Scripts\python.exe"
$env:PHOTO_PIPELINE = "C:\My_projects\Photo\src\photo_pipeline.py"
```

Перезапустить OpenCode после изменения переменных.

### Модели не найдены

Порядок поиска: `PHOTO_MODELS` → `<проект>\models` → `%LOCALAPPDATA%\rembg-env\models`. Проверить, что `models\faceparser.onnx` и `models\realesr-general-x4v3.onnx` на месте. Модель `birefnet-general` не входит в `models\`: rembg скачивает её сам.

### После переезда не находятся файлы

Старые команды и конспекты ссылались на `bg\` и `results\` в корне. Теперь это `data\bg\` и `data\results\`. Проверить, что команда запущена из `C:\My_projects\Photo` и пути начинаются с `data\`.

## Качество результата

| Симптом | Причина | Что делать |
|---|---|---|
| Фон мыльный, «пластиковый» | апскейл ×4 без размытия | `--blur 0.5–0.8` |
| Фон слишком резкий | мало размытия | `--blur` до 1.2 |
| Объект «висит» в воздухе | слабая тень | `--shadow` 0.28–0.3 |
| Фон темнее/светлее портрета | не подогнан тон | `--tone` 0.95–1.12 |
| Фон стерильный | нет зерна | `--grain` 6–8 |
| Светлый или цветной ободок по волосам | плохая вырезка | пересобрать `cut` |
| Тени на земле не совпадают с лицом | в фоне видимый источник света | выбрать фон без источника, перегенерировать |
| Кожа ушла в зелень/оранжевый | неудачный фон или `--tone` | сменить фон, вернуть `--tone` к 1.06 |
| В кадре появились люди | промпт без запрета | добавить `no people, no text` |
| Итог не того размера | фон другого формата | итог всегда равен размеру вырезки; проверить `cutout.png` |

## Диагностика фона

- Контактный лист: `src\contact_sheet.py` — сравнить варианты рядом, а не по памяти.
- Технические параметры снимка: `& $py $pp analyze "photo.jpg"`.
- Проверить, что фон действительно тот: у Cloudflare 1024×1024 до кропа, 1024×768 после; 4096×3072 — после апскейла.
