## Модели

| Файл | Размер | Для чего |
|---|---:|---|
| `models\faceparser.onnx` | 50,7 МБ | маска волос (`hair`) |
| `models\edsr-x2.onnx` | 5,5 МБ | апскейл ×2 (ручной режим, по умолчанию) |
| `models\realesr-general-x4v3.onnx` | 4,6 МБ | апскейл ×4 |

Модель ×2 — `rupeshs/edsr-onnx` (`edsr_onnxsim_2x.onnx`). В репозитории **не указана лицензия**: модель крошечная и используется локально, но для публикации/распространения проекта это нужно учесть. Альтернативы с явными лицензиями (MewZoom Apache-2.0, Swin2SR Apache-2.0, Real-ESRGAN BSD-3) мельче по деталям или в разы медленнее — сравнение на настоящих макро-снимках дало EDSR/Swin2SR ≈29 дБ против ≈27 у текущего «×4 + уменьшение», при этом EDSR не медленнее ×4 (≈2,2/3,9 с против 1,9/4,3 с на входе 512×384).

Порядок поиска: `PHOTO_MODELS` → `<проект>\models` → `%LOCALAPPDATA%\rembg-env\models`. Модель `birefnet-general` для вырезки скачивается самим rembg при первом запуске в `%USERPROFILE%\.rembg\models` (около 930 МБ).

## Кратность апскейла

`src.core.upscale.upscale(..., factor=2|4)` выбирает модель и размер выхода: при `2` используется `edsr-x2.onnx`, при `4` — `realesr-general-x4v3.onnx`. Обе модели работают через `onnxruntime` CPU, один и тот же паддинг 16 px с `BORDER_REFLECT`; обрезка и шаг тайлов умножаются на `factor` (`_run()` раньше жёстко использовал `×4`). `normalize_factor()` из `settings.py` приводит любое значение к `2` или `4`.

Ручной апскейл из GUI берёт кратность из `QSettings` → `upscale/factor` (вкладка настроек `Апскейл`, по умолчанию `2`) и передаёт её в `upscale_task()` → `upscale()`. Имя файла — `<stem>-2x` или `<stem>-4x`, старый суффикс `-2x`/`-4x` при повторном запуске заменяется. CLI: `upscale <src> <out> [--factor 2|4]`, по умолчанию тоже `2`. Ключ `models/upscale` удалён при миграции `DEFAULTS_VERSION = 2`: модель теперь однозначно следует из кратности.

Важно: `backgrounds._fit_size()` и `genbg()` вызывают `upscale()` **без** аргумента `factor`, то есть внутренняя доводка размеров фона остаётся на ×4 и не зависит от пользовательской настройки. Это сохранено намеренно, чтобы не менять поведение генерации и утверждённый стиль.

## GUI

Точка входа — `main.py` в корне проекта:

```powershell
Set-Location "C:\My_projects\Photo"
& .venv\Scripts\python.exe main.py
```

Или Run Configuration в PyCharm: script `main.py`, working directory — корень проекта.

Структура:

```text
src\ui\
├── defaults.py         проверенные предустановки и однократная миграция
├── main_window.py      окно: меню, тулбар, три зоны, вкладки предпросмотра
├── settings_dialog.py  диалог настроек (6 вкладок, сохранение в QSettings,
│                       сводка провайдера/модели, кнопка генерации)
├── workers.py          CoreWorker: QThread, прогресс, результат, отмена
└── styles.py           тёмная и светлая QSS-темы
```

Окно безрамочное (`FramelessWindowHint`). Кнопки `─` (свернуть), `□/❐` (развернуть/восстановить) и `✕` (закрыть) находятся справа в строке меню — это `cornerWidget(TopRightCorner)` у `QMenuBar`. Окно можно перетаскивать за пустое место в строке меню. Растягивание мышью работает нативно через `WM_NCHITTEST` в `MainWindow.nativeEvent()` — курсоры и поведение краёв стандартные для Windows. Углы окна скруглены радиусом 10 px (`QRegion`-маска плюс `DWMWA_WINDOW_CORNER_PREFERENCE`); в развёрнутом состоянии маска снимается.

При запуске `MainWindow._center_on_screen()` ставит окно по центру рабочей области экрана и задаёт размер √(0.85) ≈ 92,2 % по каждой стороне — это ровно 85 % площади. Учитывается `availableGeometry()`, поэтому окно не заходит под панель задач; минимальный размер 800×600 сохраняется.

Важно: в PyQt6 6.12 нельзя вызывать `super().nativeEvent()` из переопределённого метода — это даёт `access violation` и мгновенный выход при `show()`. `MainWindow.nativeEvent()` возвращает `(False, 0)` напрямую, если сообщение не обработано.

`lParam` сообщения `WM_NCHITTEST` содержит **физические** экранные пиксели, а `mapFromGlobal()` работает с логическими. При масштабе Windows 150–300 % сравнение с `self.width()` смещало зону захвата внутрь окна. Поэтому в `nativeEvent()` используется физический `RECT` из `GetWindowRect()`, а ширина зоны захвата умножается на `devicePixelRatioF()`.

Кнопки `Выбрать…` для исходного фото и фона используют ту же иконку папки (`SP_DialogOpenButton`), что и кнопка открытия фото на тулбаре.

Панель задач фиксированной ширины: `PARAMS_WIDTH = 340`, `params_zone.setFixedWidth(PARAMS_WIDTH)` в `_build_window()`. `QSplitter.setSizes([340, 900])` задаёт только стартовые пропорции — при пересчёте лэйаута (загрузка фото, генерация фона, `resize`) левая панель «убегала» (в замерах 268 → 340). Жёсткий `setFixedWidth()` ставит min = max = 340, поэтому сплиттер уже не может изменить её ширину. Второй источник смещения — `lbl_source`/`lbl_background` с `wordWrap=True`: путь Windows без точек разрыва давал `minimumSizeHint()` до 1236 px и давил на панель. `_path_label()` теперь задаёт горизонтальную политику `QSizePolicy.Ignored`, так что метка переносится внутри отведённой ширины, не влияя на размер. Регрессионный тест `test_params_panel_width_stays_fixed` проверяет `width()/minimumWidth()/maximumWidth()` и `top_splitter.sizes()[0]` после длинных путей, смены промпта, resize и загрузки картинки.

### Перевод промпта и размер фона

`src.core.prompt` решает две проблемы, из-за которых русский запрос «сделай реалистичное фото в 2К — Скалистый берег…» давал мусор. `has_cyrillic()` по наличию кириллицы включает `translate_to_english()` — запрос к публичному endpoint `translate.googleapis.com/translate_a/single` (`client=gtx`, без ключа, IPv4-патч из `settings.py`). При недоступности сервиса функция возвращает исходный текст, а `genbg_task()` пишет в прогресс «Перевод недоступен — промпт отправлен как есть». `strip_resolution()` удаляет из текста «в 2К», «in 4k» и подобные упоминания: размером управляет пресет, а не слова. `prepare_prompt()` дополняет обязательную фразу только недостающими частями (`realistic` / `no people` / `no text`), чтобы не получалось «take a realistic photo …, realistic photo, …». CLI вызывает ту же функцию, поэтому перевод работает и в GUI, и в командной строке.

`src.core.sizes.SIZE_PRESETS` задаёт конечный размер: `1K = 1024×768`, `2K = 2048×1536`, `4K = 4096×3072` (все 4:3, как у исходного снимка). Пресет живёт в `QSettings` как `bg/size` (по умолчанию `2K`) и заменяет прежний чекбокс `bg/upscale`. `MainWindow.current_params()` передаёт его в `genbg_task()` ключом `bg_size`; важно, что `run_generate()` тоже читает `params["bg_size"]` — при расхождении ключ `do_upscale` в QThread вызывает необработанное исключение и падение процесса. `genbg(..., size=...)` использует размер пресета для кропа и (у Pollinations) для запроса, после чего `_fit_size()` при необходимости делает ESRGAN ×4 и доводит файл до точного размера через `cv2.resize`. Без `size` поведение CLI сохранено: прежний `--width/--height` и `--no-upscale` работают как раньше. End-to-end проверка: русский промпт + `--size 2K` → `data\bg\arctic-ru-2k.jpg` ровно 2048×1536.

### Генерация

Генерация фона запускается из трёх точек входа: `MainWindow.tb_generate` (тулбар), `MainWindow.btn_generate` (под промптом в панели задач) и `SettingsDialog.settingsGenerate` (во вкладке `Фон` диалога). Все три вызывают `MainWindow.run_generate()`. Кнопка в диалоге работает через флаг `SettingsDialog.generate_requested`: слот `_generate()` выставляет его, вызывает `_save()` и принимает диалог; `MainWindow.open_settings()` после `Accepted` перечитывает настройки и, если флаг поднят, переносит введённый в диалоге промпт в панель задач через `SettingsDialog.prompt_text`, затем запускает `run_generate()`. Промпт больше не хранится в `QSettings`: оба поля начинаются пустыми и показывают `PROMPT_PLACEHOLDER` из `src\ui\defaults.py` (исчезает при вводе). `apply_default_presets()` и `_save()` удаляют устаревший ключ `bg/prompt`, поэтому текст прошлой генерации не появляется при старте. Кнопка под промптом в панели задач подключена в `_connect_signals()` и, как остальные кнопки обработки, выключается в `_set_busy()`.

В диалоге настроек надписи `providerInfo` (под выбором провайдера во вкладке `Модели`) и `backgroundModel` (во вкладке `Фон`) показывают активного провайдера, его модель и статус ключа. Таблица `PROVIDER_INFO` задаёт пары «заголовок · модель» для `cloudflare`, `google`, `stability`, `huggingface`, `pollinations`. Слот `_update_provider_info()` подключается к `currentTextChanged` комбо `bg/provider_api` после создания всех вкладок и вызывается в конце `_load()`, поэтому сводка актуальна сразу при открытии диалога. Наличие ключа проверяется импортируемыми из `src.core.backgrounds` функциями `cf_creds()`, `google_key()`, `stability_key()`, `hf_token()` (Pollinations показывает «ключ не нужен»). Значение `bg/model` из `controls` удалено: модель задаётся в коде провайдера либо env `PHOTO_GOOGLE_MODEL`, а в UI теперь только отображается.

Значки тулбара остаются стандартными цветными и не перекрашиваются при смене темы. Исключение — «Вырезать» и «Апскейл»: у стандартных `SP_MediaPlay` и `SP_ArrowUp` слишком тёмная заливка, поэтому `_solid_icon()` задаёт им фиксированные цвета `#16a34a` и `#0ea5e9`, читаемые и на тёмном, и на светлом фоне.


Блоки задач в левой панели (`Исходное фото`, `Фон`, `Вырезка`, `Композит`) оформлены разными цветами рамок и заголовков; цвета прописаны в обеих темах в `styles.py` (`task_source`, `task_background`, `task_cut`, `task_compose`), заголовки выделены увеличенным шрифтом.

Меню `Вид` отвечает только за компоновку: тема (тёмная/светлая), показ панели задач, панели инструментов и панели сообщений.

Масштабирование вынесено в зону предпросмотра и сделано наложенным:

- закреплённая шкала **кратности увеличения** в правом верхнем углу **страницы вкладки с фото** (внутри рамки предпросмотра, не выходит за неё) с подписями `×4 / ×2 / ×1 / ÷2`. Вместо процентов используется кратность к вписанному кадру: ползунок `ZOOM_MIN…ZOOM_MAX = −100…200`, масштаб `2 ** (value / 100)`. `0` — вписать (`×1`), минимум `−100` — вдвое меньше (`÷2`), максимум `200` — вчетверо больше (`×4`); шаг колеса — 5 единиц. Позиция фиксирована и не зависит от масштаба, размера картинки и панорамирования. Подписи занимают ту же высоту (120 px), что и ползунок, поэтому их центры совпадают с позициями ручки. Масштаб меняется ползунком или колесом мыши **в любой точке зоны фото**. Кнопка `Вписать` вынесена в заголовок зоны предпросмотра; она же сбрасывает смещение.
- лёгкий редизайн шкалы: у `QFrame#zoomBar` убрана сплошная заливка и рамка, вместо них полупрозрачный фон `$zoom_bg` с радиусом 10 px; подписи `QLabel#zoomLabel` уменьшены до 10 px и приглушены (`$zoom_text`); `QSlider#zoomSlider` получил тонкий паз 2 px и маленькую ручку 10 px. Палитры `zoom_*` добавлены в обе темы в `styles.py`.
- оверлей прозрачен в покое и проявляется не только при наведении/движении мыши, но и при своём действии: при прокрутке колеса или движении ползунка. После последнего действия панель гаснет через **5 секунд** (плавная анимация 350 мс); каждое новое действие откладывает затухание.
- фото можно перемещать при зажатой левой кнопке мыши; при наведении курсор — «открытая рука», при перетаскивании — «сжатая рука». Смещение ограничено границами картинки. Шкала пересчитывает положение по фактическому прямоугольнику изображения при зуме, панорамировании, смене вкладки и resize.

Перебор черновиков фонов **удалён**: фон загружается один раз (`Файл → Открыть фон`, генерация или апскейл). Вместе с ним убраны `NavOverlay`, стрелки `◀ ▶`, боковые кнопки мыши, сигналы `prev_requested`/`next_requested`, методы `_cycle_background()`/`_bg_files()` и стиль `QFrame#navBar`. Это устранило побочные `[OK] Фон: …` в логе во время вырезки — раньше их вызывало наведение на стрелку, а не сама вырезка. Тогда же из вкладки `Фон` настроек убраны поля-пережитки `bg/drafts` («Число черновиков») и `bg/aspect` («Соотношение сторон»): первое никогда не читалось кодом, второе заменено пресетом размера. Подсказка в поле промпта (`PROMPT_PLACEHOLDER`) теперь даёт пример «Создай реалистичное фото северного сияния на ночном небе». Поле ввода задаёт вертикальную политику `Fixed`: `QFormLayout` иначе принимает его `Expanding` за запрос расти и распределяет лишнюю высоту вкладки между всеми строками, из-за чего параметры висят с большими пропусками; теперь строки идут плотно, как в других разделах.

В рядке вкладок справа стоят `QPushButton#clearCurrent` «Очистить» (`SP_DialogDiscardButton`) и `QPushButton#saveCurrent` «Сохранить» (`SP_DirIcon`) — оба в одном `cornerWidget(TopRightCorner)` у `QTabWidget`, очистка слева от сохранения. `MainWindow._can_save_current()` разрешает сохранение только для вкладок `SAVE_TABS = ("Вырезка", "Фон", "Результат", "До — После")` и только когда все превью вкладки заполнены; состояние обновляется по сигналу `preview.moved`, смене вкладки и `_set_busy()`. `MainWindow.clear_current()` сбрасывает превью текущей вкладки через `ImagePreview.clear_image()`, для «Фон» дополнительно обнуляет `background_path` и подпись файла, после чего `_update_tab_actions()` блокирует и «Очистить», и «Сохранить». Файлы на диске не удаляются — в логе явно говорится, что очищен только предпросмотр. Кнопка скрыта на вкладке «Исходник». Для «До — После» `_combine_side_by_side()` складывает половинки в одно изображение с зазором 6 px, приводя их к общей высоте. `save_current()` открывает `getSaveFileName()`, подставляет имя по умолчанию из `SAVE_PRESETS`, пишет PNG для вырезки (с альфой) и JPG для остальных, запоминает папку в `paths/last_save_dir` и предупреждает, если для вырезки выбран JPEG (потеря прозрачности). Старый «Сохранить результат» в меню/тулбаре остался и по-прежнему пишет `data\result.jpg`.

Большие кадры после апскейла ×4 (например, 15360×8640) обрабатываются отдельно. `QImage(path)` молча возвращает пустой объект, когда декодированное изображение превышает лимит аллокации `QImageReader` (по умолчанию 256 МБ), а `QPixmap` такого размера вообще роняет процесс. `ImagePreview.set_image()` теперь вызывает `_load_qimage()`: сначала обычный `QImage`, при неудаче — `cv2.imdecode` через `_read()` (он же справляется с кириллицей в пути, в отличие от `cv2.imread`). Независимо от пути кадр уменьшается до `MAX_PREVIEW_SIDE = 4096`, поэтому превью остаётся рабочим, а полный размер хранится в `ImagePreview._source_path`. При сохранении `_save_preview_full()` и `_combine_full_res()` читают исходный файл целиком через `_read()`/`_write()`, так что «Сохранить» и «Сохранить результат» пишут полное разрешение, а не уменьшенную копию. `_set_background()` и `_show_preview()` вернули `bool` и пишут `ERROR` в лог при неудаче; `_on_operation_success()` больше не ставит `[OK]`, если кадр не показался, — именно это и давало раньше `[OK] Апскейл: …` при пустой вкладке «Фон».

В шапке зоны `ПРЕДПРОСМОТР`, между заголовком и кнопкой `Вписать`, живёт `QLabel#previewInfo` — имя файла и **настоящее разрешение** активной вкладки (`name.jpg · WxH`). Для «До — После» подписи двух половинок соединяются стрелкой (`→`). `_image_info()` берёт `WxH` из заголовка файла через `QImageReader.size()`, то есть не из уменьшенного до 4096 px превью; в tooltip попадают полный путь и вес файла. Класс `ElidedLabel` сокращает середину через `QFontMetrics.elidedText(..., ElideMiddle)`, сохраняя имя и расширение. Обновление идёт по сигналу `ImagePreview.moved` (загрузка и очистка любой вкладки) и по `QTabWidget.currentChanged` — отдельные вызовы в `open_source()`, `_set_background()`, `_show_preview()` и `clear_current()` не нужны. Дополнительного маркера «↓» нет: об уменьшении большого кадра уже говорит `AdvisoryToast`.

Подсказки о том, что делать дальше, пишутся **только в нижнее инфоокно** отдельным уровнем `[HINT]` (цвет `$c4b5fd` в `LEVEL_COLORS`), а не в строку состояния — там сообщения быстро затираются прогрессом и «Готово». `MainWindow._next_hint()` возвращает один совет по приоритету: нет исходника → открыть фото; есть, но нет вырезки → вырезать; исходник заменён после вырезки → повторить вырезку; нет фона → выбрать или сгенерировать; результат есть, а фон изменился → пересобрать; результат готов → сохранить. Перед сборкой сравниваются стороны фона и исходника через `_image_size()` (тот же `QImageReader.size()`): если фон меньше более чем на 10 %, рекомендуется апскейл с текущей кратностью из `QSettings` и явно говорится, что размер результата останется как у исходника; файл с суффиксом `-2x`/`-4x` считается уже увеличенным, чтобы совет не зацикливался; фон крупнее 4096 px получает напоминание, что превью уменьшено, а файл полного размера. `_update_hint()` пишет совет только при изменении (`_last_hint`), во время `_busy` молчит. Состояние отслеживается полями `_cut_source_path` и `_composed_bg_path`, которые выставляются в `_on_operation_success()`; обновление вызывается из `open_source()`, `_set_background()`, `clear_current()`, `_set_busy()`, `open_settings()` и `_on_operation_success()`. Подсказка ничего не запускает автоматически. Переключатель `ui/hints` на вкладке настроек `Общие` (по умолчанию `True`, значение задано в `APP_DEFAULTS`) полностью гасит вывод: `_update_hint()` сбрасывает `_last_hint`, поэтому после повторного включения актуальный совет появляется снова.

`run_compose()` больше не смотрит на `CUTOUT_FILE`: после перезапуска этот файл остаётся от прошлой сессии, и композит собирался со старой вырезкой. Теперь сборка берёт путь из `_preview_path("Вырезка")` и требует, чтобы `_cut_source_path` совпадал с текущим `source_path` и файл вырезки существовал. При отсутствии вырезки, замене исходника или исчезнувшем файле операция не запускается, а `MainWindow._action_hint()` пишет причину в инфоокно. В отличие от `_update_hint()`, этот совет не фильтруется по `_last_hint` — он должен появиться именно по нажатию кнопки, даже если звучал раньше. При отключённых подсказках та же причина выводится уровнем `WARN`, чтобы отказ не оставался молчаливым.

Об уменьшении превью пользователь уведомляется честно: `_preview_downscale()` читает размер заголовком через `QImageReader.size()` (без декодирования) и возвращает пару «было → стало», только если большая сторона превышала `MAX_PREVIEW_SIDE`. `MainWindow._warn_preview_downscale()` пишет ту же самую фразу в `AdvisoryToast` и в нижний лог уровнем `WARN` (например, `Превью уменьшено: 15360×8640 → 4096×2304 для отображения. Файл на диске и «Сохранить» — полного размера.`). Вызов идёт после `_activate_tab("Фон")`, иначе `_on_tab_changed()` успел бы погасить тост. Для небольших кадров предупреждения нет. Тот же механизм работает и для генерации фона, если провайдер выдал слишком крупный кадр.

Масштаб неактивен, если в **текущей вкладке** нет изображения: `MainWindow._has_current_image()` проверяет `source_pixmap()` у превью активной вкладки (у «До — После» достаточно любой из двух половин). Это важно для вкладок «Вырезка» и «Результат», пока они пусты. Проверку используют `PreviewArea.can_interact` (колесо), `HoverOverlay.can_reveal` и `_on_zoom_value()`/`_set_zoom_percent()` (ползунок и кнопка «Вписать»). Пока изображения нет, ползунок принудительно остаётся на 0, а оверлей не проявляется; при переходе на такую вкладку `_on_tab_changed()` сразу гасит его.

Системная шапка диалогов красится отдельно: QSS не влияет на нативный заголовок Windows, поэтому `src\ui\native_titlebar.py` выставляет атрибут DWM `DWMWA_USE_IMMERSIVE_DARK_MODE` (20, с запасным 19) на HWND диалога. `MainWindow._theme_name` хранит текущую тему, `AboutDialog` и `SettingsDialog` считывают её при создании и применяют атрибут в `showEvent()`, когда HWND уже создан. Иначе в тёмной теме содержимое было бы тёмным, а шапка с надписью «О программе» и крестиком — светлой.

Что работает: открытие исходника и фона через `Файл`, масштабирование превью, сохранение текущей вкладки кнопкой в рядке вкладок, переключение тем и панелей через `Вид`, сохранение кадра из вкладки `Результат` в `data\result.jpg`, диалог настроек с сохранением в `QSettings` (`Photo/Photo`). Тема хранится в ключе `ui/theme`, в диалоге настроек её больше нет. Диалоги открытия запоминают папку последнего файла в ключах `paths/last_source_dir` и `paths/last_bg_dir`, диалог сохранения — `paths/last_save_dir`: `MainWindow._dialog_start_dir()` проверяет, что папка ещё существует, иначе возвращает `data\`. Это избавляет от повторного перехода через проводник, когда фото грузятся из архива или с внешнего диска. После успешной загрузки исходника `_activate_tab("Исходник")` делает одноимённую вкладку текущей — пользователь сразу видит открытое фото.

Операции вырезки, генерации фона, апскейла и сборки композита запускаются кнопками тулбара и левой панели через `src.ui.workers.CoreWorker`; у генерации есть ещё кнопка в диалоге настроек (см. выше). Воркер — это `QThread` с сигналами `progress`, `succeeded`, `failed` и `cancelled`; ядро получает колбэки `progress(percent, message)` и `cancelled()` и проверяет отмену между тайлами и провайдерами (``core.progress.check_cancel``). Пока операция идёт, кнопки обработки выключены, включены обе кнопки «Стоп», прогресс показывает процент (или неопределённый режим до первого отчёта). Результат попадает в нужную вкладку: вырезка → `Вырезка`, сгенерированный/апскейленный фон → `Фон`, композит → `Результат` и правая половина `До — После`. `_on_operation_success()` после успешной вырезки или сборки вызывает `_activate_tab()` с нужным именем вкладки — если пользователь в этот момент смотрит другую вкладку, приложение переключается на результат. Для фона переключение делает сам `_set_background()`: оно срабатывает и при загрузке файлом через диалог, и после генерации/апскейла (вкладка `Фон` открывается автоматически в обоих случаях).

Промежуточные файлы: `data\work\cutout.png` и `data\work\result.jpg`; новые фоны — `data\bg\generated-<дата>-<время>.jpg` (утверждённые результаты по-прежнему лежат в `data\results\` и не перезаписываются). Апскейл по умолчанию сохраняет `<имя>-4x<расширение>` рядом с источником. Генерация автоматически добавляет недостающие части фразы `realistic photo, no people, no text`; русский промпт при этом переводится, а «2К» удаляется из текста (см. раздел про перевод).

### Предустановки и миграция настроек

Вырезка в GUI ухудшилась из-за устаревших ключей в `QSettings` (`HKEY_CURRENT_USER\Software\Photo\Photo`): там сохранились `cut/model = u2netp` и `compose/blur = 0.72`, тогда как утверждённый результат C получен с `birefnet-general` и `--blur 0.5`. Текущим кодом с дефолтными параметрами вырезка воспроизводит `cutout.png` результата C **побайтово** (SHA-256 `682C29…396E`) — значит, дело именно в сохранённых настройках, а не в рефакторинге `core`.

При запуске `main.py` вызывает `apply_default_presets(QSettings("Photo", "Photo"))` из `src\ui\defaults.py`. Функция **однократно** (ключ `app/defaults_version`, текущая версия `1`) записывает проверенные значения в `QSettings`: `cut/model = birefnet-general`, `cut/tile = 1024`, `cut/sigma = 1.4`, `cut/head_ratio = 0.34`, `cut/portrait/cut/matting = true`, `compose/blur = 0.5` (остальные параметры композита — значения по умолчанию), `bg/provider_api = cloudflare`. Ключ `bg/size = 2K` добавлен позже и для уже мигрировавших установок подставляется из `APP_DEFAULTS` как fallback — поднимать версию миграции из-за этого не нужно. Тема (`ui/theme`) намеренно не трогается. Повторные запуски при той же версии ничего не перезаписывают, поэтому пользовательские правки после первой миграции сохраняются. `APP_DEFAULTS` — единственный источник этих чисел: его используют `MainWindow`, `SettingsDialog` и сама миграция. Чтобы принудительно применить предустановки заново, нужно поднять `DEFAULTS_VERSION`.

### Качество вырезки: сетка тайлов и предупреждения

Старый `tiled_alpha()` ставил ровно два тайла по каждой оси (`[0, W - tile]`, `[0, H - tile]`) — это покрывает кадр только до 2048 px на сторону. На снимке 2592×3456 (`DSCN1941.jpg`) получалось 4 тайла и **53,2 %** непокрытой области по центру: там альфа почти нулевая, маска распадалась на 17 компонент. Все модели (birefnet-general/portrait, isnet, u2net, u2netp) на целом кадре дают похожую маску с захватом земли — низкий контраст (σ≈31 против 77 у утверждённого фото) не даёт модели чёткой границы объект/фон.

`tiling_plan(H, W, tile)` в `src\core\cutout.py` теперь строит полную сетку: для стороны ≤ `2 * tile` сохраняется унаследованная схема из 2 тайлов (поэтому `cutout.png` результата C воспроизводится побайтово, SHA-256 `682C29…396E`), для больших кадров — шаг `tile // 2` (50 % перекрытия) с прижатием последнего тайла к краю. На `DSCN1941.jpg` стало 4×6 = 24 тайла, непокрытых областей 0 %, альфа в старой «дыре» ≈0,53; время вырезки ~408 с.

Ещё один сбой модели обнаружен на `Изображение 017 — копия.jpg` (2048×1536): левый тайл 1024×1024 не содержит объекта, и `birefnet-general` возвращает для него сплошную маску (coverage 1,0) — в результате левая половина кадра оставалась непрозрачной. По кадру целиком модель правильно даёт 0 % в левой трети, а тот же тайл с захватом соседней области (1536×1536) — 16 %. Поэтому `_tile_with_context()` при coverage > 0,9 повторяет сегментацию с контекстом `tile // 2` вокруг и вырезает исходную область. На «017» левая треть стала полностью прозрачной (mean 0,0), время вырезки ~102 с. На утверждённом фото максимальный coverage тайла 0,61 — повторов нет, SHA-256 прежний.

На том же `DSCN1941.jpg` после полной сетки остался замкнутый «провал» 566×532 px (~253 тыс. px) внизу фигуры: вокруг альфа ≈1, внутри ≈0,05; по бокам внизу тоже были пробелы. Первый опыт `fill_enclosed_holes()` (заливка по топологии альфы) дал неверный оттенок: pymatting брал цвет почти прозрачного участка, и в дыре получилось BGR `[127,77,72]` вместо исходных `[111,64,65]`. Он удалён. Вместо него используется ранний H-рецепт `C:\Users\bur_s\AppData\Local\rembg-env\bg_remove.py`: цельный кадр без тайлов, растяжение альфы 8…247, жёсткие пороги (≤5 → 0, ≥250 → 255), медиана 3. `global_shape_alpha()` в `src\core\cutout.py` воспроизводит его, `merge_global_shape()` добавляет только области с `whole > 0,9` и `alpha < 0,5` (мягкий край Gaussian σ=3), а если таких пикселей <0,1 % кадра — маску не трогает. Слияние идёт до pymatting, поэтому цвет в восстановленных областях берётся из исходника (дыра: `[110,64,64]`). На утверждённом фото совпадающих пикселей 0,0158 % (315 px) — ниже порога, SHA-256 остаётся `682C29…396E`. H-рецепт сам по себе не годится как замена тайлам: на «017» он не чистит левый фон, а тайлы с контекстом справляются; поэтому схема гибридная — тайлы основа, цельный кадр страховка.

`cut_advisory(src)` возвращает списки предупреждений (большой кадр с числом тайлов, низкий контраст). `MainWindow._update_source_advisory()` дублирует их в лог уровнем `WARN` и показывает `AdvisoryToast` — всплывающее уведомление в правом верхнем углу страницы вкладки `Исходник`, левее шкалы масштаба. Класс наследует `HoverOverlay`: та же анимация прозрачности 350 мс и таймер 5 с; крестик — `CloseButton(QPushButton)` внутри `QHBoxLayout`, прижат к верхнему краю через `Qt.AlignmentFlag.AlignTop` (иначе он центрируется по высоте многострочного текста), вызывает `dismiss()` (мгновенное закрытие), уход с вкладки тоже закрывает тост. `CloseButton.paintEvent()` после `super()` рисует две сглаженные линии цветом `palette().buttonText()` — так крест не зависит от глифа шрифта и остаётся читаемым в обеих темах. Важно: `QRect::center()` у чётного размера (22×22) возвращает `(10, 10)` вместо `(10.5, 10.5)`, поэтому центр считается как `(left + right) / 2`, `(top + bottom) / 2` — иначе крест визуально смещается вверх-влево внутри квадрата. Подсказок при наведении (`setToolTip`) у тоста и кнопки нет. `show_notes()` сначала вызывает `show()`, а уже потом `adjustSize()` — иначе скрытый виджет не разкладывает лэйаут и крестик остаётся невидимым с нулевой геометрией. Уведомление **не занимает место в слое** — в отличие от прежней постоянной подсказки, оно не отодвигает превью и не остаётся на экране после загрузки фото. Стиль `QFrame#advisoryToast` (жёлтая рамка `$warning`, заметная кнопка `×`) задан в обеих темах `styles.py`.

Что пока не сделано: «живой» предпросмотр композита при движении ползунков (сборка запускается только кнопкой).

Старый шаблон `src\windows_pq.py` оставлен без изменений как визуальный референс (стили, пропорции сплиттеров); новые импорты из `src.core.*` и `src.service_modules.*` в проекте отсутствуют, поэтому он не запускается.

Тесты лежат в `tests\` и используют stdlib `unittest` (pytest в окружении не установлен):

```powershell
Set-Location "C:\My_projects\Photo"
& .venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```

Qt запускается в режиме `offscreen` (`QT_QPA_PLATFORM=offscreen`), а `QSettings` подменяются на изолированные `IniFormat`-объекты во временной папке — тесты не читают и не меняют настройки реального приложения. В этой сборке PyQt6 `QSettings.setDefaultFormat()` не влияет на `QSettings("Photo", "Photo")`, поэтому подстановка делается через патч модулей `src.ui.main_window` и `src.ui.settings_dialog`, а формат задаётся явно.
